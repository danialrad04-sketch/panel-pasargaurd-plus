# نصب و آزمون فورک بومی PasarGuard Plus

این راهنما برای همین فورک و شاخهٔ `feat/donino-integration` است. اسکریپت نصب upstream، قابلیت‌های این فورک را نصب نمی‌کند. سناریوی هدف: پنل روی سرور مستقل، نود ایران و نود آلمان هر دو متصل به پنل، ترافیک کاربران از ایران از طریق آلمان، انتشار IP ایران در اشتراک.

## ۱. نصب تازهٔ پنل روی Linux

Docker Engine، Compose v2، Git و دسترسی ساخت image لازم است. برای اولین تست از محیط و دیتابیس مستقل استفاده کنید.

```sh
git clone --branch feat/donino-integration https://github.com/danialrad04-sketch/panel-pasargaurd-plus.git
cd panel-pasargaurd-plus
cp .env.example .env
docker compose build
docker compose up -d pasarguard
docker compose logs --tail=100 pasarguard
docker compose ps
```

داشبورد داخل Docker از سورس همین فورک ساخته می‌شود؛ ساخت دستی `dashboard/build` لازم نیست. اولین build شامل دریافت وابستگی‌های Python و frontend است. `DEBUG=false` نگه دارید. تنظیمات TLS و آدرس پنل را در `.env` کامل کنید. پنل بدون TLS برای دسترسی محلی مناسب است؛ برای تست اولیه می‌توان پورت محلی را با SSH forward کرد. برای لینک اشتراک روی دستگاه واقعی از دامنه و HTTPS معتبر استفاده کنید. راهنمای تنظیمات فعلی پاسارگارد همچنان برای HTTPS/reverse proxy کاربرد دارد.

Compose به‌صورت پیش‌فرض دیتابیس را در `/var/lib/pasarguard/db.sqlite3` ذخیره می‌کند. اگر `SQLALCHEMY_DATABASE_URL` را در `.env` تعیین کرده‌اید، همان مقدار حفظ می‌شود. **ارتقای نصب قبلی:** پیش از تغییر مسیر دیتابیس، از دیتابیس و کلیدها نسخهٔ پشتیبان سازگار بگیرید؛ URL فعلی را حفظ کنید یا دیتابیس را در حالت توقف سرویس به volume منتقل کنید. تغییر مسیر به یک فایل خالی، انتقال اطلاعات قبلی نیست. `start.sh` migration را قبل از شروع API اجرا می‌کند.

کلید یک‌بارمصرف ساخت مالک:

```sh
docker compose exec pasarguard pasarguard-cli generate-temp-key
```

در صفحهٔ راه‌اندازی مالک، کلید را همراه نام کاربری و رمز قوی وارد کنید. کلید خصوصی است، پنج دقیقه اعتبار دارد و فقط یک بار مصرف می‌شود. رمز/کلید را در issue یا تصویر عمومی قرار ندهید.

## ۲. نصب تازهٔ نود روی هر دو سرور

سورس کامل نود و Paqet در `node/` وجود دارد؛ فورک جداگانه برای شروع لازم نیست. روی هر سرور همین شاخه را دریافت کنید. دستور آماده‌سازی فقط برای **نود جدید** است؛ UUID و گواهی نود موجود را تغییر ندهید.

```sh
cd panel-pasargaurd-plus/node
sudo python3 prepare_node.py --address YOUR_NODE_IP --name Iran
sudo docker compose -f compose.plus.yml build
sudo docker compose -f compose.plus.yml up -d
sudo docker compose -f compose.plus.yml logs --tail=100
```

روی آلمان، IP و نام آلمان را وارد کنید. Python 3 و OpenSSL لازم است. `--address` باید IP عددی قابل دسترس باشد؛ برای چند SAN می‌توانید آن را تکرار کنید. `--state-dir` مسیر دادهٔ میزبان و `--port` / `--tunnel-port` پورت‌های مدیریتی را تنظیم می‌کنند. گواهی مستقل یک‌ساله و UUID مستقل تولید می‌شوند؛ انقضا و تمدید گواهی را در نگهداری سرور در نظر بگیرید. ابزار از بازنویسی فایل‌های موجود خودداری می‌کند.

فایل `.env` و `node-registration.json` خصوصی هستند. فایل JSON شامل CA عمومی و API key است، کلید خصوصی TLS داخلش نیست. آن را از مسیر امن به دستگاه مدیریت منتقل کنید. در پنل ← نودها ← افزودن گره ← «واردکردن فایل ثبت نود بومی»، JSON همان سرور را انتخاب کنید، هسته را بررسی کنید و سپس ذخیره کنید. واردکردن فایل به‌تنهایی نود را ثبت یا deploy نمی‌کند. پس از ثبت مطمئن شوید هر دو نود `connected` هستند. برای نود موجود از گواهی و UUID فعلی و volume قبلی استفاده کنید؛ نمونهٔ راه‌اندازی جدید را روی دادهٔ موجود اجرا نکنید.

پورت‌های `62050/TCP` برای مدیریت نود و `62052/TCP` برای API افزونهٔ Paqet باید از پنل قابل دسترس باشند؛ دسترسی آنها را به IP پنل محدود کنید. پورت raw حامل بین دو نود و پورت‌های ورودی کاربران ایران نیز باید مطابق تنظیمات قابل دسترس باشند. هر دو نود ارتباط مدیریتی مستقل خود با پنل را حفظ می‌کنند. دسترسی `NET_ADMIN` و `NET_RAW` و libpcap برای حامل Paqet لازم است؛ این روش داخل کانتینر فاقد این دسترسی‌ها کار نمی‌کند.

## ۳. مسیر ایران به آلمان و سابلینک

1. ورودی کاربر Xray روی ایران بسازید؛ آدرس listen باید از سمت کاربر قابل دسترس باشد، نه فقط `127.0.0.1`. کاربر، گروه، ورودی و هاست الگوی موجود را به روش بومی پنل تنظیم کنید.
2. در «تونل‌های بومی نودها» مسیر جدید بسازید: مبدا ایران، خروجی آلمان و tag ورودی کاربران ایران. حامل SS2022 یا Paqet را انتخاب کنید. برای تونل کامل domains را خالی بگذارید؛ برای مسیر انتخابی، دامنه‌ها را مشخص کنید.
3. برای Paqet، قابلیت هر دو نود، تنظیمات NIC/IP/MAC و پورت raw را بررسی کنید. راهنمای [تنظیمات Paqet](NATIVE-PAQET.fa.md) جزئیات همهٔ گزینه‌ها و محدودیت‌های فوروارد/SOCKS را توضیح می‌دهد.
4. «بررسی آمادگی» را اجرا کنید. این بررسی فقط تشخیص تنظیمات و کنترل نود است. «نیاز به اصلاح» روی runtime مانع تشخیص آمادگی انتشار است؛ اعمال مجدد برای تعمیر همچنان ممکن است.
5. مسیر را فعال و «اعمال روی نودها» را اجرا کنید؛ این کار هستهٔ نودهای مرتبط را restart می‌کند و می‌تواند اتصال فعال را قطع کند. نتیجهٔ هر دو سمت و revision اعمال‌شده را بررسی کنید.
6. در بخش هاست‌ها «افزودن ورودی تونل به سابلینک» را بزنید؛ مسیر، هاست الگو، IP ایران و پورت **ورودی کاربر ایران** را انتخاب کنید. پورت raw Paqet، API مدیریت یا SS داخلی را به کلاینت ندهید. تنظیمات TLS/SNI/transport از الگو حفظ می‌شوند.
7. سابلینک واقعی کاربر را تازه‌سازی کنید و کانفیگ ایران را در کلاینت اجرا کنید. اصلاح/چرخش کلید/غیرفعال‌سازی مسیر، هاست وابسته را تا تأیید revision لازم از خروجی اشتراک پنهان می‌کند؛ تست این رفتار را هم انجام دهید.

جزئیات: [انتشار هاست تونل](TUNNEL-SUBSCRIPTION-HOSTS.fa.md).

## ۴. DNS اختیاری

`DNS_ENABLED` و پروتکل‌های دلخواه را در `.env` فعال کنید. تنظیمات پیش‌فرض resolver برابر `127.0.0.1:5335` است. پروفایل زیر worker DNS و Unbound محلی را همراه پنل بالا می‌آورد:

```sh
docker compose --profile dns up -d
docker compose --profile dns logs --tail=100 dns resolver
```

Unbound فقط روی loopback پورت 5335 گوش می‌دهد؛ آن را عمومی نکنید. اگر resolver فعلی روی این پورت دارید، تعارض را برطرف یا upstream سفارشی را تنظیم و سرویس resolver همراه را متناسب با نصب خود تغییر دهید. حساب DNS، سیاست دامنه‌ها، credential و IP lease را در پنل تعریف کنید. DoH با credential و UDP/TCP/DoT با مجوز IP مطابق راهنمای DNS کار می‌کنند؛ پورت 53 ممکن است با resolver سیستم تعارض داشته باشد.

**SmartDNS بومی و DNS روی نود اضافه شده‌اند:** برای relay مجاز TCP/UDP، سهمیهٔ بایتی و خروج از تونل نود، [راهنمای عملیات](NATIVE-OPERATIONS.fa.md) را دنبال کنید. DNS resolver به‌تنهایی relay نیست؛ حساب، IP lease، gateway، مسیر خروجی و اعمال تنظیمات لازم‌اند.

## ۵. چک‌لیست پذیرش روی سرور خودتان

- ورود پنل، ثبت دو نود، قطع و وصل و reboot هر سمت و حفظ اطلاعات پس از جایگزینی کانتینر.
- کانفیگ کاربر در ایران، اتصال TCP و UDP، DNS و یک بازی/سرویس مشخص؛ سنجش latency/loss/throughput روی همان ISP.
- افزایش مصرف همان کاربر و اعمال محدودیت حجم؛ فوروارد و SOCKS اضافی Paqet از quota بومی VPN استفاده نمی‌کنند.
- حذف/ابطال credential DNS و IP lease، سقف QPS و حجم، پاسخ UDP و TCP و DoH/DoT در صورت فعال‌بودن.
- غیرفعال‌سازی و اعمال مسیر، پنهان‌شدن هاست وابسته و برگرداندن مسیر؛ شکست سمت خروجی نباید به موفقیت یا عبور آزمایش‌شده تعبیر شود.

این مرحله هیچ VPS، دامنه یا فایروال شما را تغییر نمی‌دهد. پایش حامل، failover با بازگردانی و SmartDNS gateway اکنون پیاده‌سازی شده‌اند؛ فعال‌سازی و پذیرش شبکه‌ای مطابق [راهنمای عملیات](NATIVE-OPERATIONS.fa.md) لازم است. حامل‌های دیگر همچنان نیازمند adapter و آزمون مستقل هستند.

## شواهد نصب در checkpoint پیشین `88cb15f7`

در محیط Linux محلی، ۳۸۴ آزمون منتخب پاس شدند: ۲۶۰ آزمون DNS/تونل/Paqet/هاست/کش/چرخهٔ نود و آماده‌سازی، ۱۲۰ آزمون API و اشتراک، ۲ آزمون ترافیک TCP/UDP با Xray واقعی و ۲ آزمون Docker نسخهٔ production. آزمون Docker ساخت مالک، ورود، healthcheck، اجرای داشبورد واقعی، بازشدن فرم نود با تأخیر بارگذاری، ورود فایل ثبت بدون ذخیرهٔ خودکار، حفظ دیتابیس پس از جایگزینی کانتینر و Unbound محلی روی UDP/TCP را پوشش داد.

جریان مرورگر متصل به API برای انتشار هاست/سابلینک و بررسی آمادگی و همچنین ویرایش تنظیمات Paqet پاس شد. TypeScript، build تولیدی، Ruff و اعتبارسنجی فایل‌های Compose نیز موفق بودند. این نتایج مربوط به آزمون محلی هستند؛ در این مرحله تست دو نود Paqet واقعی و کلاستر NATS دوباره اجرا نشده و پذیرش بازی/ISP روی VPS شما انجام نشده است.


نتایج جدید پایش، DNS نود، gateway، NATS و بازیابی در [NATIVE-VALIDATION.fa.md](NATIVE-VALIDATION.fa.md) ثبت شده‌اند. اعداد بخش بالا مربوط به checkpoint قبلی هستند.


برای هستهٔ تونل با Paqet اصلی و Backhaul/GOST/FRP، [راهنمای چندموتوره](NATIVE-ENGINE-CORE.fa.md) و [شواهد تست جدید](ENGINE-CORE-VALIDATION.fa.md) را ببینید. API قبلی و حساب کاربران حفظ شده‌اند.
