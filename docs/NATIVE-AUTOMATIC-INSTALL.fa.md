# نصب و راه‌اندازی خودکار تونل از پنل

در نسخهٔ جدید این فورک، نصب نود، انتقال چهار هسته و راه‌اندازی مسیر از صفحهٔ **تونل‌ها** انجام می‌شود. برای روش معمول، ورود به ترمینال هر نود، دانلود هسته و انتقال فایل ثبت لازم نیست. پنل باید با Dockerfile جدید همین مخزن ساخته شده باشد؛ اجرای قدیمی یا اجرای مستقیم سورس بدون بستهٔ نصب، این بسته را ندارد.

## مسیر استفاده

۱. با حساب مالک به «تونل‌ها ← نصب و راه‌اندازی خودکار ← نصب خودکار روی سرور» بروید. سرور تازه یا نود موجود را انتخاب کنید. IP و پورت SSH، کاربر root یا کاربر دارای sudo بدون رمز، و رمز SSH یا کلید خصوصی را وارد کنید. برای نود موجود، هسته و پورت‌های ثبت‌شده حفظ می‌شوند.

۲. «بررسی هویت SSH سرور» را بزنید و اثر انگشت نمایش‌داده‌شده را با هویت سرور تطبیق دهید. این بررسی اولیه بدون ارسال رمز انجام می‌شود. شروع نصب، کلید میزبان نمایش‌داده‌شده را pin می‌کند؛ تغییر کلید، قبل از ارسال رمز اتصال را متوقف می‌کند.

۳. «شروع نصب خودکار روی این سرور» را بزنید. پنل بستهٔ کامل Node، Paqet، Backhaul، GOST، FRP server/client، Xray و داده‌های جغرافیایی را منتقل می‌کند؛ وابستگی‌های لازم سیستم را نصب، سرویس systemd را فعال، نود را ثبت و روشن‌شدن هسته را بررسی می‌کند. انتخاب موتور در این فرم برای بررسی نصب است؛ هر چهار موتور نصب می‌شوند. پیشرفت و خطا در همان صفحه باقی می‌مانند.

۴. پس از آماده‌شدن دو نود، «تونل جدید» را بزنید، نود ایران را مبدا و آلمان را خروجی انتخاب کنید. موتور، پروفایل و ورودی‌های کاربر را تعیین کنید و «ذخیره و راه‌اندازی خودکار» را بزنید. پنل پورت حامل را برای peer لازم تنظیم، خروجی و سپس مبدا را اعمال و TCP/UDP حامل رمز‌شده را واقعاً بررسی می‌کند. پورت‌های عمومی ورودی انتخاب‌شده فقط بعد از تأیید راه‌اندازی هسته باز می‌شوند. «ذخیره مسیر» برای ذخیرهٔ صرف نیز باقی است.

۵. برای نمایش IP ایران در سابلینک، گزینهٔ هاست وابسته به مسیر را در بخش هاست‌ها انتخاب کنید؛ قواعد آمادگی و انتشار هاست بومی همچنان اعمال می‌شوند. راه‌اندازی حامل به‌تنهایی تأیید اتصال کاربر، پورت عمومی هاست یا کیفیت بازی نیست؛ کانفیگ فروخته‌شده را از دستگاه مشتری هم آزمایش کنید.

تغییر موتور در مسیر جدید پس از این نصب به SSH دوباره نیاز ندارد. نصب اولیهٔ پنل و ارائهٔ دسترسی اولیهٔ سرورها همچنان لازم است؛ پنل نمی‌تواند بدون هیچ دسترسی قبلی وارد سرور شود.

## شرایط فعلی

- مقصد Debian 12 یا Ubuntu 22.04 و نسخه‌های جدیدتر با systemd فعال، و root یا sudo بدون رمز است. نصب‌کننده با Python 3.10 به بالا سازگار است؛ Python در صورت نبودن از APT نصب می‌شود.
- بستهٔ تصویر پنل، معماری همان تصویر را دارد: amd64 یا arm64. معماری متفاوت باید بستهٔ معتبر خودش را در تصویر/مسیر بسته‌ها داشته باشد؛ نبودن آن خطای روشن می‌دهد. پذیرش عملی این مرحله روی amd64 انجام شده است.
- خود هسته‌ها از بستهٔ داخل پنل منتقل می‌شوند و روی نود نیاز به GitHub یا کامپایل ندارند. دریافت وابستگی‌های غایب سیستم به دسترسی سالم APT نیاز دارد.
- مسیرهای مدیریت SSH و API نود باید از پنل قابل دسترس باشند. فایروال ارائه‌دهندهٔ VPS، security group یا NAT خارج از سیستم‌عامل با دسترسی SSH مدیریت نمی‌شوند. قواعد متعلق به سرویس در chain جدا ایجاد می‌شوند؛ سیاست کلی فایروال و قواعد SSH جایگزین نمی‌شوند.
- نود قبلی فقط با همان CA، کلید API، مسیر state و پورت‌ها ارتقا می‌یابد. Docker قبلی فقط وقتی قابل تشخیص و متعلق به همین Plus باشد متوقف می‌شود؛ کانتینر برای بازگشت نگهداری می‌شود. سرویس یا هویت ناشناخته خودکار بازنویسی نمی‌شود.
- هویت TLS تازه گواهی یک‌ساله دارد. تمدید خودکار گواهی در این تغییر پیاده‌سازی نشده است.

## نگهداری و بازیابی

SSH فقط برای نصب استفاده می‌شود. اطلاعات ورود در صف با AES-GCM و کلید خصوصی `0600` رمز می‌شوند و در پایان موفق، خطا یا لغو حذف می‌شوند؛ در پاسخ API، جزئیات job و audit قرار نمی‌گیرند. کلید پنل به‌صورت خودکار در volume پایدار `/var/lib/pasarguard/provisioning.key` ایجاد می‌شود. تمام workerهای نود باید همان کلید و همان بسته‌ها را ببینند. فایل کلید را عمومی نکنید.

کارها در دیتابیس پایدار، با مالکیت محدود زمانی، heartbeat، محدودیت هم‌زمانی و جلوگیری از نصب هم‌زمان روی یک مقصد اجرا می‌شوند. قطع worker به تلاش محدود برای ادامهٔ همان کار منجر می‌شود. لغو فقط پیش از شروع مجاز است؛ قطع نصب در حال تغییر سرویس به‌عنوان لغو امن اعلام نمی‌شود. بازگردانی backup، کارهای نصب فعال را متوقف و اطلاعات ورود آن‌ها را پاک می‌کند تا نصب SSH قدیمی دوباره اجرا نشود.

releaseها محتوامحور و hashشده‌اند. شکست تعویض سرویس، لینک release، فایل unit و تنظیمات اجرای قبلی را برمی‌گرداند؛ شکست هرگز با نتیجهٔ «آماده» نمایش داده نمی‌شود. پس از خطا وضعیت نود و سرویس مقصد را بررسی کنید و با همان نود موجود دوباره نصب را انتخاب کنید.

متغیرهای اختیاری پنل: `NATIVE_BUNDLE_DIRECTORY` و `NATIVE_PROVISION_KEY_FILE`. مقدار پیش‌فرض تصویر رسمی همین فورک کافی است. نقش `node` یا `all-in-one` صف نصب را اجرا می‌کند؛ نقش‌های دیگر فقط درخواست را ثبت می‌کنند.
