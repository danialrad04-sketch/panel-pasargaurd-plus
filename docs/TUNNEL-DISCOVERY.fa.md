# تشخیص تونل‌های موجود (Paqet، V2Ray، DNS)

برای سروری که از قبل تونل ایران ← آلمان دارد (Paqet دستی، کانفیگ V2Ray/Xray که از تونل رد می‌شود، مسیر DNS). هدف: **اول ببینیم چه چیزی هست، بعد پنل را طوری ببندیم که رویش ننویسد.** هیچ بخشی از تشخیص چیزی را تغییر نمی‌دهد.

## تضمین‌ها

- **فقط‌خواندنی.** اسکریپت از stdin اجرا می‌شود؛ روی سرور فایل نمی‌نویسد، نصب نمی‌کند، سرویسی را restart یا فایروال را تغییر نمی‌دهد. دستورهایش فقط `iptables-save`، `ip6tables-save`، `nft list ruleset`، `ip -j addr`، `systemctl is-active/is-enabled` هستند.
- **رمز و کلید همان‌جا حذف می‌شوند.** کلید KCP، رمز SOCKS، UUID کاربران، `privateKey`، `shortIds`، توکن‌ها و کاربر/رمز داخل URL پیش از خروج از سرور با `***` عوض می‌شوند. فقط ساختار، پورت و آدرس‌ها می‌آیند.
- **رمز SSH ذخیره نمی‌شود.** فقط در حافظه برای همین اتصال با هویت SSH تأییدشده (fingerprint) استفاده می‌شود.
- **فقط مالک پنل** می‌تواند اجرا کند.

## چه چیزی پیدا می‌شود

| مورد | از کجا |
|---|---|
| Paqet (کلاینت ایران / سرور آلمان)، peer، پورت raw، SOCKS/forward، interface، router MAC | پردازش `paqet*` و فایل yaml آن |
| Backhaul، FRP، GOST، kcptun، udp2raw، socat، ssh -L/-R | پردازش‌ها و کانفیگ‌ها |
| V2Ray/Xray/sing-box: inbound ها و outbound هایی که به پورت محلی تونل وصل‌اند | json کانفیگ؛ پیوند «outbound → تونل» و «مقصد خروجی تونل ← inbound» |
| مسیر DNS: forward به ۵۳/۸۵۳، unbound/dnsmasq/smartdns | forwardهای Paqet و سوکت‌های گوش‌دهنده |
| قوانین فایروال Paqet (NOTRACK و RST drop) | iptables/nft؛ **قوانین این پنل** (`pg-plus-paqet-*`) از قوانین **دستی** جدا می‌شوند |
| سرویس systemd، فعال/غیرفعال، پایداری پس از reboot | واحدهای systemd |

هشدارها: پردازش بدون کانفیگ یا کانفیگ بدون پردازش، نبود قوانین فایروال، قوانین مشترک بین پنل و دستی، پورت raw روی ۸۰/۴۴۳/۵۳، اجرا بدون systemd، دو Paqet روی یک پورت، سرور بدون دسترسی root.

## استفاده

1. داشبورد ← تونل‌ها ← **تشخیص تونل‌های موجود**.
2. IP و دسترسی SSH را بدهید، «بررسی هویت SSH» را بزنید و fingerprint را با سرور تطبیق دهید، بعد «شروع بررسی فقط‌خواندنی».
3. نتیجه را مرور کنید. اگر پنل چیزی دارد که با سرویس موجود روی یک پورت است، تداخل با دلیل و راه‌حل نشان داده می‌شود.
4. **رزرو پورت‌ها** را بزنید. از آن لحظه پنل این پورت‌ها را برای تونل جدید، ویزارد، gateway، DNS و نصب نود برنمی‌دارد و اگر کسی دستی بخواهد، ۴۲۲/۴۰۹ با نام پورت می‌گیرد.

رزرو فقط مانع دست‌زدن پنل است؛ تونل موجود را مدیریت نمی‌کند و تغییر نمی‌دهد. با «آزادسازی» برمی‌گردد.

### بدون SSH از پنل

روی خود سرور: `sudo pasarguard-plus detect` (یا `sudo python3 app/discovery/collector.py > facts.json`). خروجی را با `POST /api/tunnel/discovery/analyze` به پنل بدهید.

## رزرو کجا اعمال می‌شود

اعتبارسنجی هر تونل بومی، تخصیص خودکار پورت در ویزارد تونل سریع، مسیرهای gateway و پورت DNS، و فرم نصب خودکار نود. پورتی که پنل همین حالا روی همان سرور استفاده می‌کند را نمی‌شود رزرو کرد؛ ابتدا سمت پنل را عوض کنید.

## محدودیت‌ها

- تونل‌هایی که داخل Docker اجرا می‌شوند دیده می‌شوند، ولی کانفیگ داخل کانتینر خوانده نمی‌شود.
- پنل‌های مبتنی بر پایگاه‌داده (مثل x-ui) فقط از روی `config.json` تولیدشده تحلیل می‌شوند.
- تشخیص «سالم‌بودن تونل» انجام نمی‌شود؛ فقط وجود، نقش و پورت‌ها. پایش واقعی بعد از ورود تونل به مدیریت پنل است.
- با سرور واقعی ایران/آلمان آزمایش نشده؛ نتایج روی داده‌ی ساختگی و یک پردازش واقعی محلی تست شده‌اند.
