# نقشه راه حرفه‌ای‌سازی DNS گیمینگ

هدف: DNS گیمینگ از «کار می‌کند» به «قابل فروش، قابل کنترل و قابل عیب‌یابی» برسد.
مرجع الهام: Doctor DNS (دسترسی با IP ثبت‌شده، سهمیه، محدودیت سرعت، ابزار watch، صفحه کاربر).

## اصول

1. **یکدستی با کاربر پنل.** DNS یک حساب جدا نیست؛ هر چیزی (انقضا، حجم، وضعیت، دسترسی مدیر) از خود کاربر می‌آید.
2. **هیچ ادعای ثابت‌نشده.** هر قابلیتی که روی نود و شبکه واقعی آزمایش نشده با برچسب «آزمایش‌نشده» می‌ماند.
3. **هر مرحله مستقل قابل تحویل و قابل تست باشد**؛ پنل بدون تغییر نود هم کار کند.
4. **امن‌بودن پیش‌فرض.** لینک کاربر فقط IP خودش را ثبت می‌کند؛ ورودی‌ها محدود؛ همه تغییرات audit می‌شوند.

## فاز ۱ — سمت پنل (قابل تست کامل همین‌جا)

| # | قابلیت | چرا | معیار پذیرش |
|---|---|---|---|
| 1.1 | **کشف دامنه (watch)**: فهرست نام‌هایی که یک کاربر اخیراً پرسیده، با برچسب «از gateway»، «مستقیم» یا «مسدود» | بازی جدید یا خراب را بدون حدس پیدا کنیم | مدیر برای هر کاربر ۲۰۰ پرسش اخیر را می‌بیند؛ حافظه محدود؛ بدون ذخیره دائمی تاریخچه سایت‌ها |
| 1.2 | **افزودن دامنه به پروفایل** از همان فهرست | چرخه «بازی کار نمی‌کند ← دامنه را بفهم ← اضافه کن» در یک صفحه | دامنه به سیاست و مسیر gateway اضافه، اعتبارسنجی و روی نود اعمال شود؛ سقف ۲۵۶ مسیر رعایت شود |
| 1.3 | **مصرف به تفکیک سرویس** (روزانه، ۳۰ روز) | کاربر و مدیر ببینند حجم کجا رفته | فقط «سرویس، روز، بایت»؛ هرگز فهرست سایت‌ها؛ در صفحه DNS و اشتراک دیده شود |
| 1.4 | **سقف سرعت هر کاربر** (فیلد، API، UI، قرارداد grant) | فروش پلن‌های متفاوت | مقدار در grant به نود برسد؛ ۰ = نامحدود |

## فاز ۲ — سمت نود Go (نیازمند ساخت با Go 1.27 در CI)

در این محیط Go 1.27 و وابستگی‌ها قابل دانلود نیست، پس تغییر Go اینجا کامپایل نمی‌شود. این فاز فقط با CI یا ماشین دارای toolchain تحویل داده می‌شود.

| # | قابلیت | توضیح |
|---|---|---|
| 2.1 | اعمال سقف سرعت | token bucket برای هر اتصال/کاربر بر اساس `rate_bps` در grant |
| 2.2 | صفحه «ورود به شبکه» | IP ثبت‌نشده یا کاربر منقضی، به‌جای قطع کامل، به صفحه لینک DNS هدایت شود (فقط HTTP) |
| 2.3 | پوشش UDP | بسیاری از بازی‌ها UDP‌اند؛ بدون آن «بازی روان» ادعا نمی‌شود |
| 2.4 | DoT/DoH روی نود | DNS رمزنگاری‌شده برای دستگاه‌هایی که DNS ساده را تغییر می‌دهند |

## فاز ۳ — تجاری‌سازی (بعد از اعتبارسنجی)

پلن‌ها (قالب حجم/روز/سرعت)، فروشنده‌ها (reseller) با سقف، کیف پول و پرداخت، ربات تلگرام، اعلان ۸۰٪ و ۹۵٪ حجم.
بیشتر این‌ها روی سیستم کاربر/قالب/ادمین فعلی پاسارگارد سوار می‌شوند، نه سیستم موازی.

## فاز ۴ — اعتبارسنجی واقعی (بدون این، «حرفه‌ای» ادعا نمی‌شود)

1. نصب روی یک نود ایران و یک خروجی خارج، با DNS گیمینگ روشن.
2. تست روی PS5/Xbox/PC: دانلود فروشگاه، matchmaking، NAT type، تأخیر.
3. فهرست دامنه‌های هر بازی از watch (۱.۱) استخراج و به کاتالوگ اضافه شود.
4. ثبت نتیجه برای هر بازی: «کار می‌کند / فقط فروشگاه / کار نمی‌کند».

## ریسک‌ها

- بازی‌های UDP و بازی‌هایی که DNS را دور می‌زنند با این معماری پوشش داده نمی‌شوند.
- هزینه ترافیک تقریباً دو برابر است (ورودی + خروجی روی relay).
- ثبت IP توسط کاربر با CGNAT/IP مشترک سازنده خطاست؛ سقف ۳ IP و ۶ تغییر در روز آن را محدود می‌کند.
