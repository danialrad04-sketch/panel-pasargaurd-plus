# ادغام دونینو در PasarGuard Plus

این تغییر، مدیریت نصب Donino Tunnel را به تب «تانل دونینو» در بخش نودها اضافه می‌کند و صفحه پیش‌فرض ساب را بازطراحی می‌کند. کاربران، سهمیه‌ها، TLS و خروجی اشتراک همچنان توسط پاسارگارد مدیریت می‌شوند.

## راه‌اندازی

1. نقش ایران Donino Tunnel را روی میزبان پنل و نقش خارج را روی سرور مقصد طبق [راهنمای دونینو](https://github.com/danialrad04-sketch/donino-tunnel/blob/main/docs/role-setup.md) نصب کنید. این ادغام با قرارداد کنترل‌کننده نسخه ۰.۴.۰ و کد فعلی مخزن بررسی شده است.
2. سرویس `donino-control` و socket روت `/run/donino-control/control.sock` باید آماده باشند. socket نباید برای سایر کاربران مجوز داشته باشد. سرویس پاسارگارد باید از طریق گروه `donino-link` به آن دسترسی داشته باشد.
3. متغیر `DONINO_TUNNEL_BRIDGE=1` را فقط در محیط سرویس API پاسارگارد تنظیم و سرویس را مجدداً اجرا کنید. bridge پیش‌فرض خاموش است. این متغیر اطلاعات محرمانه ندارد. در systemd می‌توان `SupplementaryGroups=donino-link` را در drop-in سرویس موجود افزود؛ نام سرویس را از نصب خودتان بگیرید.
4. در Docker، socket میزبان را در همان مسیر bind mount و GID گروه میزبان را با `group_add` به کانتینر اضافه کنید؛ نصب کنترل‌کننده داخل کانتینر API لازم نیست. دسترسی به socket قدرت نصب روی هر دو سرور دارد.
5. به‌عنوان مالک پنل وارد تب نودها ← تانل دونینو شوید. کد جفت‌سازی پنل خارج، IP/دامنه خارج و پورت مدیریت را وارد کنید. کد در پاسخ API، مرورگرِ ذخیره‌شده یا log این ادغام ثبت نمی‌شود.
6. کانال مدیریت را تست کنید، آدرس ایران و پورت‌ها را وارد کنید، حامل‌ها را انتخاب و پیش‌نمایش بسازید. در حالت فعلی مقصد هر سرویس `127.0.0.1` روی خارج است؛ inbound باید واقعاً روی همان میزبان و آن پورت آماده باشد. اتصال خودکار به رکورد نود پاسارگارد هنوز وجود ندارد.
7. پورت‌های پیش‌نمایش را بررسی و پس از تأیید جایگزینی نصب قبلی، نصب دوطرفه را آغاز کنید. این ادغام فایروال را خودکار باز نمی‌کند. تاریخچه از worker خوانده می‌شود و بعد از بارگذاری صفحه باقی است.

حامل‌های قابل انتخاب: FRP WSS/QUIC و با انتخاب صریح آزمایشی، BackPack، Paqet، Backhaul، BrowserLink، Donino Mux و Continuum. تنظیمات پایه پورت‌ها و سرویس‌های TCP قابل تنظیم‌اند؛ پارامترهای اختصاصی KCP/FEC/smux/PCAP و بازیابی Continuum از این فرم قابل ویرایش نیستند و از پیش‌فرض کنترل‌کننده استفاده می‌کنند. برای تغییر تنظیمات اختصاصی فعلاً پنل مستقل دونینو مرجع است؛ نصب دوباره با پیش‌فرض می‌تواند تنظیمات اختصاصی نصب قبلی را جایگزین کند.

## قرارداد API و خطا

تمام مسیرهای `/api/tunnels/*` از احراز هویت و dependency مالک پاسارگارد استفاده می‌کنند. کلید API در پاسارگارد owner نمی‌شود. مسیرها: `GET /state` و `POST /pair`، `/connection`، `/preview`، `/start`. ورودی‌های ناشناخته رد می‌شوند، مقصد Unix socket ثابت است، پاسخ‌ها از فهرست مجاز عبور می‌کنند و متن خطای upstream به کاربر منعکس نمی‌شود. خطای schema پاسخ نیز ۵۰۲ است. مهلت شبکه ۹۰ ثانیه و سقف پاسخ ۲ MiB است. bridge نه shell اجرا می‌کند و نه مقصد HTTP دلخواه می‌پذیرد.

موفقیت job فقط موفقیت عملیات نصب است؛ سلامت فعلی و عبور واقعی VPN را اثبات نمی‌کند. پس از timeout، عملیات نصب را بدون بررسی وضعیت worker دوباره شروع نکنید. شروع نصب retry خودکار ندارد. worker مسئول قفل نصب و انقضای نقشه است. API پاسارگارد در این مرحله audit مستقل عملیات و binding دیتابیس به inbound ندارد.

## صفحه ساب

رابط فارسی و RTL، چیدمان موبایل، تم روشن/تیره با ترجیح سیستم و انتخاب ذخیره‌شده، حجم باقی‌مانده و مصرف، تاریخ پایان، وضعیت on-hold، بازنشانی دوره، جستجو، نام اتصال از fragment، کپی همه/تک، QR محلی با dialog قابل بستن با Escape، برنامه‌های پیشنهادی و راهنمای اتصال فراهم است. محاسبه حجم باقی‌مانده و درصد برای مصرف بیشتر از سقف محدود می‌شود. اشتراک غیرفعال/منقضی/پایان حجم لینک اتصال نشان نمی‌دهد. لینک و نام‌ها autoescape و نام fragment با textContent درج می‌شود.

هیچ درخواست سرویس بیرونی برای ساخت QR ارسال نمی‌شود. فونت از فونت سیستم استفاده می‌کند. قالب سفارشی تنظیم‌شده توسط اپراتور طبق رفتار موجود بر قالب پیش‌فرض اولویت دارد و این تغییر آن را جایگزین نمی‌کند. برای مشاهده طرح جدید، قالب پیش‌فرض `subscription/index.html` باید انتخاب شده باشد. این نسخه فارسی است؛ بومی‌سازی سایر زبان‌های صفحه ساب مرحله بعد است.

## مرز این تغییر

این نسخه انتقال کامل Donino Panel یا دیتابیس آن نیست. DNS/Smart DNS، OpenVPN، مدل دستگاه و حسابداری دونینو، پایش خودکار VPN، انتشار leaseدار آدرس تونل در اشتراک، ابزارهای runtime حامل‌ها و backup دونینو هنوز به مدل پاسارگارد منتقل نشده‌اند. انتقال آنها به migration، RBAC، حسابداری و آزمون‌های مستقل نیاز دارد. آدرس host اشتراک خودکار تغییر نمی‌کند؛ پیش از انتشار آدرس ایران باید اتصال واقعی و تنظیمات TLS آن بررسی شود. استقرار روی VPS کاربر انجام نشده و آزمون محلی جای پذیرش دو VPS یا اینترنت ایران نیست.

کد bridge با اقتباس از `donino-panel/app/tunnel_bridge.py` در مخزن همین مالک، تحت مجوز AGPL-3.0 پروژه‌ها منتقل و برای aiohttp و احراز هویت پاسارگارد سازگار شده است. نسخه‌های مبنا در گزارش تحویل ثبت می‌شوند.

## شواهد توسعه

مبنای پاسارگارد: `5eb8628cfe6db233ed2a6bbaf53f0ed497e797f9`؛ مبنای Donino Panel: `cdad7417e58f212cc7b453089a8dbf6cdba9ef9c`؛ مبنای Donino Tunnel: `4c19214598d32bd2868f9f46030d8a5dbd494d97`.

آزمون‌های این تغییر:

```sh
uv sync --group dev
uv run pytest tests/test_donino_integration.py tests/test_donino_subscription_template.py tests/test_app_factory.py -q
cd dashboard
npm install --legacy-peer-deps --ignore-scripts --package-lock=false
npm run typecheck
npm run build
# در ترمینال جداگانه: npm run dev -- --port 4173
node scripts/test-donino-ui.mjs
```

نصب npm با legacy-peer-deps فقط برای اجرای بررسی در این محیط لازم شد؛ وابستگی موجود qrcode.react نسخه ۳ با peer React ۱۹ ناسازگار است. manifest و lock پروژه تغییر نکردند؛ برای نصب معمول پروژه، workflow مبتنی بر Bun و lock موجود مرجع است. build با هشدار موجود chunkهای بزرگ و externalization ماژول crypto تمام شد.

۴۴ آزمون بک‌اند، قالب و رگرسیون شامل Unix socket واقعی محلی، رد مجوز عمومی socket، سقف پاسخ، redirect، پاسخ نامعتبر، عدم افشای خطای upstream، نقش مالک، تأیید صریح و وضعیت‌های ساب پاس شدند. آزمون UI از fixture API استفاده می‌کند و هیچ نصب واقعی را اجرا نمی‌کند. مرورگر واقعی Chromium، مسیر پیش‌نمایش تا نصب، حذف نقشه بعد از ویرایش، الزام تأیید، غیرفعال‌بودن bridge، دسترسی غیرمالک و عرض موبایل را بررسی کرد.
